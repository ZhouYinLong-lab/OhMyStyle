## 简介

这类游戏美术用手绘场景承载探索、观察和交互。它重视前中后景、入口、遮挡和可行走空间，也重视笔触如何表现墙面、地面、植被与空气。本包提取的是二维手绘场景的构建方法，不是某一部游戏的画面复制。

## 策展短评

我喜欢它介于插画和空间设计之间的状态：画面可以有明显的笔触，却不会失去“我能走进去看看”的清楚感。做这类包时，最重要的不是额外塞进角色和谜题，而是把环境本身画得足够可读，让用户的主体有地方落脚。

## 主体独立性

本包只决定媒介、场景层级和手绘处理，不规定角色、地点、谜题、幻想元素或故事。代表图使用普通公共空间作为中性测试主体，新的生成应以用户需求为准。

## 来源与版权

研究入口为[诺伊玛游戏开发者网站](https://noemagames.com/)。仓库不打包外部游戏画面、角色或界面；代表图是新的匿名场景，不是任何游戏的截图，也不表示合作、授权或背书关系。

## 只使用此包

### 方式一：交给有生图能力的 Agent

把本目录交给 Agent，让它先读取 `identity.yaml`、`visual-signature.yaml`、`reproduction.yaml`、`prompts/`、`palette/palette.json` 和 `evaluation.yaml`，再编译你的主体、场景、画幅和用途。生成后按评价文件检查空间层级和主体独立性。

### 方式二：直接复制 Prompt

打开 `prompts/base.txt`，替换 `{{SUBJECT}}`、`{{ASPECT_RATIO}}` 和 `{{USE_CASE}}`；把 `prompts/negative.txt` 一并提交给支持负面 Prompt 的平台。

### 方式三：配置 API Key 后提交生成

在你自己的生图平台或编译工具中配置 API Key，提交基础 Prompt、负面约束和调色板。本仓库不托管密钥或在线生图服务。

### 方式四：本地模型 + ComfyUI

将 Prompt、调色板和复现说明接入本地模型或 ComfyUI，生成后用 `evaluation.yaml` 检查层级、材质、笔触和 AI 痕迹。不要把代表图的楼梯或车站当成默认场景。
