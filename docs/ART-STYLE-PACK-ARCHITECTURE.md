# 美术风格包架构提案

状态：设计草案；研究日期：2026-10-18。本文及配套设计 YAML 是美术内容的设计样稿。现已增加三个可选试点并进入 `main`，实际支持范围、运行文件与使用命令见 [v2 试点说明](../experiments/style-v2/README.md)；尚未完成生图对照验证。

当前架构与执行边界的统一说明见 [美术风格包架构详解](ARCHITECTURE.md)。本文保留方案推导、参考实践与后续设计建议。

## 1. 建议采用的方案

保留现有独立包，按制作团队的 Art Bible 思路改进内容：一个包描述一个有边界的视觉方向，以可观察的规则、带分析的参考作品、制作过程和对照结果共同说明它。

核心结构是：

**范围与意图 → 视觉规则 → 参考与反例 → 制作与执行 → 跨题材验证。**

Getty 的形式分析提供描述词汇，Valve 的 TF2 制作实践提供从视觉目标到制作规则的示范，Bauhaus Dessau 的教学资料帮助区分学院方法与成品画风。Firefly 和 InstantStyle 则提示生成执行中应区分风格参考、构图参考和主体内容。这些实践分别解决不同问题；下文的字段、文件安排和验收建议是本项目的综合设计，并非它们共同发布过的标准。

第一阶段复用 identity.yaml、visual-signature.yaml、reproduction.yaml、relations.yaml、evaluation.yaml 和已有来源清单，只为参考分析与样例记录补充两种可选侧记。把 visual-signature.yaml 作为视觉规则的唯一来源；Prompt 和评估项通过规则 ID 与它对应。

在几种可选路线中，建议把 Art Bible 与结构化规则作为包的核心，图像参考、模型适配器或专门渲染器作为可选执行能力：

| 路线 | 适合承担的职责 | 对本项目的不足 |
| --- | --- | --- |
| 风格名称与关键词 | 成本低的基线，利用模型已有知识 | 无法说明模型具体继承了哪些视觉决定，换模型后含义可能改变 |
| 单张风格参考图 | 快速表达表面、颜色与整体感受 | 一张图把主体、构图与风格混在一起；需要内容泄漏检查 |
| 特定模型的适配器或 LoRA | 在明确模型与数据范围内实现专门风格控制 | 模型依赖、训练或推理设置也是效果的一部分，不能直接当成通用定义 |
| Art Bible、规则与对照证据 | 记录可解释的视觉方向，支持多种执行方式 | 需要作品研究与评审；规则写得具体也仍需生图验证 |

这是一项架构选择，不是四类方法效果优劣已经得到实验排序。

## 2. 参考了哪些已有实践

| 实践 | 可复用内容 | 应保留的限制 |
| --- | --- | --- |
| [Getty：Elements of Art](https://www.getty.edu/education/teachers/building_lessons/formal_analysis.html) 与 [Principles of Design](https://www.getty.edu/education/teachers/building_lessons/formal_analysis2.html) | 用线、形、空间、明度、色彩、纹理描述图像，并观察平衡、节奏和视觉权重 | 这是分析词汇，不能单凭这些通用维度认定某位艺术家的特征 |
| [Valve：Illustrative Rendering in Team Fortress 2](https://cdn.steamstatic.com/apps/valve/2007/NPAR07_IllustrativeRenderingInTeamFortress2.pdf)，尤其第 3–4 节 | 把插画目标落实到剪影、明暗组织、细节取舍、材质和着色方式，并检查实际输出 | 这些规则属于 TF2 的选定视觉方向，不能套给所有插画或游戏 |
| [Bauhaus Dessau：教学](https://bauhaus-dessau.de/en/knowledge/teaching/) 与 [纸材预备课程](https://bauhaus-dessau.de/en/visit/groups/offers-for-students/) | 从具体课程、材料实验和制作任务定义学院包；纸材练习可落实为切、撕、折等操作 | 当前教育项目是对历史方法的传承和转译，不应直接称为历史原作 |

| [InstantStyle：论文](https://arxiv.org/abs/2404.02733) 与 [作者实现](https://github.com/instantX-research/InstantStyle) | 参考图会带入内容；风格和内容的解耦需要专门处理 | 论文方法和作者示例不证明它对本仓库所有包有效，需实测；也不能承诺完全消除内容泄漏 |
| [索罗亚：伦敦国家美术馆技法介绍](https://www.nationalgallery.org.uk/exhibitions/past/sorolla/bright-colours-bold-brushstrokes-and-unexpected-angles) | 从机构分析提取速写性笔触、光线与取景等可研究方向 | 一篇文章和一幅代表作不足以证明艺术家所有时期共享同一套不变量 |

上一轮提到的 Riot VFX 指南仍可作为历史参考。此次打开旧文章和 PDF 地址时均跳转到游戏首页，因此不把它列作当前可直接访问的主要验证材料，也不附带未经核实的镜像下载地址。

本次没有运行外部生图产品、下载模型权重或产生评分。可运行研究方法优先参考 InstantStyle 作者仓库；需要直接交互试验时，可按 Firefly 官方说明操作。

## 3. 现有包暴露出的美术问题

抽查现有文件，而非对全部包做艺术质量定论：

- [索罗亚视觉签名](../style-packages/artists/joaquin-sorolla/visual-signature.yaml) 已有较具体的光线、反射色与笔触规则，但尚未把每条规则与来源证据、适用条件逐条连接。
- [包豪斯视觉签名](../style-packages/schools/bauhaus/visual-signature.yaml) 的 medium.name 是 school。学院是来源类别，无法作为油画、摄影、纸材、字体或金属构造这样的媒介使用。
- 各包的视觉签名结构存在列表、嵌套轴和大段摘要等不同形态。相似的形容词可能出现在多个包里，缺少实际可比的视觉判据。
- [ASCII 包](../style-packages/game-art/ascii-character-game-art/README.md) 已经采用字符源网格与逐格渲染。这是应当保留并推广的媒介约束实例；普通生图方式不能替代它。
- ASCII 的现行视觉签名还写着“字号变化建立距离”，而严格渲染器使用统一字号和单元格。试点需要消除这一类美术说明与制作约束之间的矛盾。
- [当前编译器](../tools/style_runtime.py) 读取现行多文件契约。新样稿中的字段还不会自动变成生图控制，接入需要单独实施。
- [旧比较工具](../tools/compare-style.py) 面向 style.yaml 的词汇重合。它的数值不能充当当前包的美术区分度，也不能证明图片风格相同。

通用的“高质量、保持风格、避免普通滤镜”可以当编辑提醒，不能作为包的核心区别。读完一个成熟包，应能回答：轮廓如何形成、明暗如何分组、颜色如何互相作用、什么细节被舍弃，以及换一个主体后哪些决定仍成立。

## 4. 五个美术层的职责

~~~mermaid
flowchart TD
    A["范围与意图：时期、媒介、任务边界"] --> B["视觉规则：少量核心支柱与可观察判据"]
    R["原作与机构资料"] --> C["参考分析：证据、局部、反例、使用许可"]
    C --> B
    B --> D["制作与执行：工序、媒介约束、模型能力"]
    U["用户题材、数量、构图与用途"] --> D
    D --> E["新输出与源文件"]
    E --> F["规则审查、题材遵循、近邻对照"]
    F --> G["样例记录与适用范围更新"]
    G --> A
~~~

### 4.1 范围与意图：这个包具体代表什么

艺术家、学院和流派不是相同粒度的研究对象。目录可以继续按来源浏览，但每个可执行方向必须说明取样范围。

| 来源类别 | 应定义的内容 | 范围控制 |
| --- | --- | --- |
| 艺术家 | 选定时期、媒介或工作方式中的稳定视觉决定 | 允许一个艺术家有多个明确方向；不要把全部生涯压成单一滤镜 |
| 摄影师 | 取景、光线、空间、距离、动态、色调与后期处理 | 区分拍摄行为和输出效果；不用虚构镜头、胶片或曝光数据解释未核实的结果 |
| 艺术流派 | 有代表性的共同策略、内部差异和适用媒介 | 可以有方向分支；共享历史特征不需要被人为改写成互斥特征 |
| 艺术学院 | 特定课程、工作坊、导师时期或设计方法 | 未研究清楚时先给方法说明；学院名称不自动产生唯一成品画风 |
| 技法 | 材料、操作、痕迹和物理或数字构建约束 | 工艺造成的痕迹应可解释；不能只在成图表面叠纹理 |
| 游戏美术 | 视觉语言、交互可读性、镜头和技术限制 | 固定角色与关卡不是默认主体；像素或字符约束须真实执行 |
| 原创预设 | 明确的视觉目标与可调整范围 | 以设计目标负责，无须冒认历史归属 |

identity.yaml 记录上述范围和内容策略；visual-signature.yaml 中不再重复传记。

主体独立也需要明确表现方式：

- recognizable：保持对象可辨认，可改变呈现方式。
- stylized：允许比例或形体概括，但保留用户要求的身份和数量。
- abstract_interpretation：把用户概念转译为抽象关系，需用户明确选择。
- nonfigurative：以非具象构成为目标，不承诺还原用户指定对象。

用户要求具象椅子与纯非具象方向冲突时，应报告不兼容并给出可选转译方式；不能静默牺牲题材，也不能自动加入椅子来假装满足非具象风格。原有 subject_policy.open 继续表示“不强加固定主体”，与上述表现模式是两件事。

### 4.2 视觉规则：从形容词变成可作出的决定

每包先选约 3–5 个核心支柱作为编辑起点，再用足够的规则说明它们。这个数量是本项目试点建议，不是美术史定律或行业统一标准。

分析词汇可覆盖下列维度，不要求每包全部填写：

| 维度 | 应回答的问题 |
| --- | --- |
| 构图与层级 | 大形如何分组，视觉重量、疏密、焦点和留白如何组织？ |
| 形与体 | 轮廓、比例、体块如何简化或变形？ |
| 线、边缘与笔触 | 线如何转折，哪里硬、哪里软，痕迹是否跟随形体？ |
| 明度 | 亮暗如何分区，对比集中在哪里，灰阶下是否成立？ |
| 色彩关系 | 主次色、冷暖、饱和度与相邻色如何作用？ |
| 光线 | 光源如何塑造形体，阴影与反射怎样处理？ |
| 空间 | 透视、平面化、景深、尺度和遮挡怎样工作？ |
| 材质与表面 | 纸、颜料、金属、皮肤等如何显示不同表面行为？ |
| 细节与纹理 | 哪些细节保留、哪些舍弃，纹理密度如何变化？ |
| 制作或捕获过程 | 材料、工序、摄影行为怎样造成可见结果？ |
| 领域扩展 | 动画节奏、游戏可读性、像素网格、字符集等特定要求 |

一条规则包含：

~~~yaml
id: colored-shadow-structure
axis: color
importance: core
applies_when: "当前方向及任务包含可见的受光面与阴影面"
instruction: "用环境反射色组织暗面，并保留对象的局部颜色关系。"
observable: "阴影中的色相变化帮助读出体块，灰阶中仍保有明暗组织。"
reject_when: "只罩一层暖色，暗面仍是无结构的中性黑。"
evidence:
  source_ids: [source-id-from-manifest]
  basis: curatorial_inference
  visual_review: pending
~~~

importance 区分核心、辅助、可选。媒介硬约束单列为 hard_constraints，不与“更有笔触感”等软偏好混用。

evidence.basis 可用 institutional_description、direct_visual_observation、curatorial_inference、original_design_intent。观察原作、转述机构说明和编辑推断必须区分；pending 不自动变成 verified。没有合适证据的规则可用于试验，但不能被包装为已证明的历史事实。

色板先定义角色与关系。HEX 是锚点而非每张图的精确直方图；硬性限色包则需另写允许色集与量化规则。

规则之间还要有少量联合判据。例如日光方向里，环境反射色应帮助说明体块，笔触应跟随同一体块；纸材方向里，开口、折线和投影应共同解释空间。分别出现“蓝色阴影”“可见笔触”“几何轮廓”，不意味着它们已经形成一致的视觉语言。联合判据只引用已有规则 ID，不另维护一份重复规则。

### 4.3 参考与反例：把风格判断变成可对照的材料

references/manifest.csv 继续负责来源、作者、权利和可分发状态。新增可选 references/analysis.yaml，只按 asset_id 连接分析，不重复录入整份来源。

每项分析记录：支持哪些规则、观察了哪个局部、哪些是作品主体而不能默认迁移、观察状态，以及是否可作为实际模型输入。不能再分发的作品仍可保留链接；link-only 记录不会自动转成可上传的风格图。

四种图像角色应当明确：

1. 原作或一手作品：研究证据，不伪装成生成样例。
2. 风格输入图：实际提供给模型的素材，需单独记录本次用途与可用权限。
3. 目标样例：经过评审的新输出，用于说明包希望达到的效果。
4. 诊断反例：指出某条规则具体失效的图；优先使用同任务、只改变少量因素的对照。

成图和分析最好形成一个小型对照页：整体图、必要局部、灰阶或轮廓诊断、规则说明。由原作制作的局部或诊断图仍受原素材使用条件约束，不能因做了分析就默认为可分发。

代表图用于导航，不能独自证明跨题材效果。只有色板卡时展示为色板卡，不把它算作目标样例。样例不足时应明确暴露“待验证”，避免用数量和精致封面代替效果证据。

### 4.4 制作与执行：让视觉意图落实到媒介

reproduction.yaml 说明工序和必要控制。不是每个包都走同一条文生图通路：

| 执行方式 | 适合用途 | 输出证据 |
| --- | --- | --- |
| text_only | 便携地测试规则本身 | 实际提交的完整 Prompt、模型与设置 |
| style_reference | 模型具备独立风格输入时保持材质、色彩或线性特征 | 实际输入图 ID、用途、强度、模型版本 |
| structure_control | 用户需要保持构图、轮廓、深度或布局 | 独立的结构来源及参数；须由任务明确授权 |
| deterministic_grid | ASCII、严格网格像素、图块等构建任务 | 源网格或图块数据、渲染代码、字体或调色板及输出 |

这四种方式是本提案的执行分类，并非所有平台的同名参数。文本规则、风格图和结构图分别传入可用通路，不能仅把所有文件名拼进 Prompt。

规则编译应保留规则 ID、适用条件、优先级和冲突。用户要求的题材、数量、场景与构图先进入任务；包只对可兼容的视觉决定施加约束。遇到媒介或风格核心冲突时返回具体冲突，不自动用更强的风格词覆盖用户要求。

ASCII 的硬约束是可打印字符、固定网格、逐格渲染和场景形状来源可追踪。文字模型可以生成源网格；图像模型补笔触或重绘字符会使该路径失效。像素包是否允许抗锯齿、半透明、色阶与缩放方式应逐包声明，不能套用一条通用“复古”约束。

摄影、油画、平面设计、纸材实验各自保留媒介逻辑。对不适用的维度可以写 not_applicable，避免给学院练习强加景深、给黑白线描强加油画高光。

### 4.5 评估：同时检查风格、题材与近邻差异

evaluation.yaml 的检查项引用 rule_id；可另有与任务相关的主体遵循、数量和图形完整性检查。规则不适用时记录原因并从本次分母排除，不能把没有水面的场景扣成“缺少水面反射”。

顺序为：

1. 先查硬约束与输出有效性。ASCII 未交付真实网格，就不能由高美观分抵消。
2. 检查用户任务是否完成；主动选择的抽象转译按约定评，不与具象任务混评。
3. 对适用的核心规则逐项审查，附局部证据与失败解释。
4. 检查换题材后能否保持关键视觉决定。
5. 对容易混淆的相邻包做相同任务盲评，说明共享之处及可观察差异。

建议试点用 0–4 的有说明评分：0 相反或缺失，1 仅有泛化暗示，2 部分成立，3 清楚成立，4 多处一致且服务整体画面。此量表用于试验设计，发布阈值待实测校准。不能只凭平均分升级成熟度，核心规则失败应单列。

relations.yaml 可记录 shared_traits、distinguishing_rules 和 comparison_status。艺术家与所属流派可以有真实重叠；不以“所有包必须看起来完全不同”为目标。差异不够证据支持时，缩小范围、增加方向分支或承认当前无法可靠区分。

## 5. 怎样复用现有文件

| 文件 | v2 设计职责 |
| --- | --- |
| package.yaml、resource.yaml | 保持包身份、发现和现行资源契约；本提案不调整它们的运行格式 |
| identity.yaml | 研究对象、时期、媒介范围、表现模式、主体策略和不兼容请求 |
| visual-signature.yaml | 视觉支柱与规则的规范源，包含规则 ID、适用条件、可观察现象和证据连接 |
| reproduction.yaml | 制作工序、执行方式、媒介硬约束和能力要求 |
| palette/palette.json | 颜色角色、关系及必要的精确色值 |
| relations.yaml | 有依据的共享特征、近邻差异、可组合维度与冲突 |
| references/manifest.csv、provenance.yaml | 沿用来源与权利记录 |
| references/analysis.yaml（可选新增） | 作品级分析、规则证据和内容泄漏风险 |
| prompts/ | 由规则形成的便携文本或经维护的执行版本，记录对应规则版本 |
| evaluation.yaml | 引用规则 ID 的审查项、硬约束和任务指标 |
| examples/manifest.yaml（可选新增） | 输出、源文件、模型、输入图、设置、规则版本、评审状态 |
| README、代表图、对照页 | 面向使用者展示范围、效果与限制；格式化内容可以生成，策展判断仍需维护 |

兼容策略：先在设计区验证新结构；接入时让加载器明确区分现行结构与 v2 结构。现有文件中的重复描述可在迁移时转成规则 ID 或生成视图。未完成适配前不把样稿复制到正式包，防止出现“文件已升级、编译器实际忽略”的假兼容。

## 6. 三个有区别的样稿

完整字段示例位于 [设计目录](design/art-style-pack-v2/)：

- [sorolla.yaml](design/art-style-pack-v2/sorolla.yaml)：选择索罗亚户外日光油画实践作为研究方向，检查光线、反射色、明暗分组和有方向的笔触。禁止默认塞入沙滩；参考作品的跨作品视觉复核仍待进行。
- [bauhaus-paper.yaml](design/art-style-pack-v2/bauhaus-paper.yaml)：选择 Albers 预备课程纸材方法的当代转译，围绕切、撕、折、受力和材料经济性构建。不能把它宣称为所有包豪斯作品的唯一画风。
- [ascii-grid.yaml](design/art-style-pack-v2/ascii-grid.yaml)：用源网格、字符集、字形映射和渲染过程证明媒介成立。它的验收包含代码可检查条件。

这些 YAML 是多文件内容的合并展示，便于评审；其中各段注明将来对应的现有文件。它们不是三次新增正式包，也不记录未经发生的 accepted 输出。

## 7. 先怎样证明方案有用

[comparison-plan.yaml](design/art-style-pack-v2/comparison-plan.yaml) 提供可自行执行的比较矩阵。先用三个难点不同的方向做小规模筛选，再决定迁移：

| 试点 | 核心问题 | 初步验证方式 |
| --- | --- | --- |
| 索罗亚 | 新规则能否跨题材保持日光与笔触逻辑，又不泄漏海滩内容？ | 同模型下，名称提示、旧包规则、新规则三组；三个日光下的中性题材，每题两次输出，共 18 张 |
| 包豪斯纸材 | 方法型学院方向能否产生可解释的材料区别？ | 同模型下，泛化学院词、当前包规则、新材料方法三组；三个纸材任务，每题两次输出，共 18 张 |
| ASCII | 真实字符构建能否保持源与结果对应？ | 三个不同布局的网格任务，每个做一次独立源生成及一次同源重渲染；生图近似只作诊断参照，不算合格路径 |

18 张是用于发现问题的筛选预算，不是统计显著性的承诺。两个生成试点合计 36 张，另有 ASCII 源文件与渲染输出；首次结果不外推为全部 406 个包有效。

初筛后再增加风格参考组：同样任务下比较规则文本与规则加参考图。只有平台能明确区分风格和结构输入、素材可用于该次请求时才运行。不能把产品自动重写 Prompt、模型差异或参考图内容带入误认为规则改进。

记录模型及版本、日期、实际完整 Prompt、支持的负面约束、输入素材 ID、设置、种子（如果支持）、输出和评审。固定种子只用于同实现内尽量减少变化，跨模型或服务不保证相同噪声，也不保证线上服务严格复现。

评审先隐藏组名，观察题材完成度与逐规则表现，再看组别和生成设置。近邻对比追加同题材的 Monet、De Stijl 或像素包作为诊断；相似度、色彩统计和图像嵌入只辅助找问题，不能替代美术判读。

通过试点的依据应包括：适用核心规则有稳定的可见证据，主体遵循没有明显退化，内容泄漏未被放大，媒介硬约束通过，且评审能解释相对旧包的改善和失败。若只让封面更漂亮、换题材即失败，保留为研究草稿。

## 8. 落地顺序

[迁移成本与保真评估](ART-STYLE-MIGRATION-ASSESSMENT.md) 对实施顺序作了进一步限定：先在实验区旁路增强，建立现行运行基线和显式新执行方式；通过同题材比较后再启用具体方向。不能用全库自动补齐字段替代美术研究，也不能把当前编译器读入 YAML 误当作它已将视觉规则编译进 Prompt。

1. 确认本草案的范围、视觉维度、规则结构和三份样稿；补齐作品级视觉研究。
2. 为三个试点编写实际 Prompt 与任务；用真实模型和 ASCII 渲染路径执行对照，保存全部结果。
3. 根据结果删掉无作用字段，调整规则粒度与评分，再实现兼容加载和 ID 检查。
4. 优先迁移区别不清、学院范围过大、参考证据不足或媒介执行错误的包；成熟包不必因目录整齐而重写。
5. 对通过的规则生成用户说明与编译文本，保持视觉规则、评估和展示可追踪。

本提案暂不引入全量重命名、统一强制色板、自动艺术家分类分数或一套“总审美分”。优先证明规则有作用、范围诚实、媒介成立、相邻风格的差异有证据。
