评估日期：2026-10-18。基线版本：59d9aa10ee9eeaedf3b815688d00f3e553ef31ea。评估对象是 [美术风格包架构草案](ART-STYLE-PACK-ARCHITECTURE.md)；本轮只做盘点、读取和内存探查，没有改写正式风格包。

后续实施已另行开展：旧版保存在远端标签 `style-v1-snapshot-2026-10-18` 和分支 `codex/style-v1-preserved`；新入口最初在 `codex/style-pack-v2` 实施，现已进入 `main`，后续开发继续使用 `main`。索罗亚日光、莫奈、印象派、点彩、包豪斯纸材方法、严格 ASCII 网格、梵高方向性笔触、莫兰迪静谧色阶、霍普建筑光影、艾格尼丝·马丁手绘网格、卡拉瓦乔明暗对照、广重气象版画、北斋轮廓色面、弗里德里希人的尺度、欧姬芙近距离观察、莱利光学节奏、丢勒刻线明暗、穆夏装饰海报、安娜·安彻居室窗光、阿尔泰米西娅身体动作构图、比亚兹莱墨块与留白、莫里索手势笔触与开放边缘、里维拉公共叙事壁画层次、委拉斯开兹目光与纵深、德加偏置观察与空间裁切、席勒轮廓张力与纸白负形、蒙克心理色彩与环境节奏、利西茨基 Proun 轴测空间、格列柯垂直升腾与闪烁形体、卡罗正面肖像与个人象征关系和卡萨特人物与装饰平面组织、透纳天气光线与运动、戈雅心理肖像与选择性笔触、伍德乡土景观图案与垂直节奏已作为可选实验规则登记于正式包。参见 [试点使用与回退说明](../experiments/style-v2/README.md)。下文保留评估时的统计；其中 American Luminism 标题的 YAML 引号问题已单独修复，未批量改写美术规则。

## 1. 结论与方案修订

不建议对 406 个包做一次性语义迁移。建议先在独立实验目录里人工整理三个方向，提供明确选择的新执行路径，与现行输出对照；通过后再逐包启用。

脚本适合做保真提取、引用检查、格式校验和结果记录。将旧句子自动扩写成“视觉指令、观察标准、反例、证据、适用条件”，属于新的美术创作与研究判断；即使格式完全通过，也可能改变原风格。

本轮盘点还发现：当前本地 Prompt 编译路径没有把 visual_signature 的规则内容展开进最终文本。直接改这个 YAML 可能改变检索，却不改变同一包的生图 Prompt。因此迁移必须分别核算内容重写、执行适配和效果验证，不能把文件转换完成算作风格升级。

## 2. 实际盘点到了什么

机器可读结果见 [style-migration-inventory.json](../reports/style-migration-inventory.json)。统计以 Git 跟踪的正式包和图像为准，不把本地候选图片计入 accepted。

| 实测项 | 数量或结果 | 如何理解 |
| --- | --- | --- |
| 正式 package.yaml | 406 个 | 现有迁移范围，拆分方向后不一定仍是一对一 |
| 视觉签名的顶层键与值类型组合 | 30 种 | 这是语法形态数量，不是经过批准的 30 套 Schema |
| 成熟度记录 | 247 个 L2、159 个 L3 | 现行成熟度不能自动视为新规则验证通过 |
| 含已跟踪 accepted 图片 | 159 个包 | 文件存在不等于有 v2 逐规则评审证据 |
| 来源清单仅 1 行 | 316 个包 | 一行可能是作品，也可能只是搜索页或介绍；不能当作跨作品证据 |
| 来源清单至少 2 行 | 84 个包 | 多行不一定是多个原作，仍需判断支持范围 |
| 来源清单没有数据行 | 6 个包 | 对原创设计或方法类包需检查设计依据，不能一律当作缺少历史原作 |
| 清单含本地素材路径 | 28 个包 | 不保证这些素材都是原作、可直接上传或适合当风格参考 |
| 已有拟议 rules[].evidence 结构 | 0 个包 | 仅指本草案的结构尚未采用，不表示所有旧规则都没有文字来源 |

另外阅读了 12 个包的视觉签名片段，覆盖全部七类来源。它们显示了不同工作量：

- Agnes Martin、Cézanne 等包已有较具体的视觉关系，适合保留原句、梳理条件和补证据。
- Henri Cartier-Bresson 等包的主要特色集中在短摘要，正文含较多通用约束。新格式若想更具体，需要新的作品研究。
- Bauhaus、RISD 等学院包首先要决定具体课程或方法范围；这不是键名映射问题。
- ASCII 包需要把文字里的字号变化与实际固定网格约束统一，属于制作规则审查。

上述例子不能用来对全库自动划分艺术质量等级，也不能据此计算“百分之多少无需人工”。

## 3. 当前执行路径的实测风险

检查了 [加载与 Prompt 编译](../tools/style_runtime.py)、[检索](../tools/ohmystyle_core.py) 和 [组合编译](../tools/composite_runtime.py)：

| 路径 | 现行行为 | 对迁移的影响 |
| --- | --- | --- |
| 加载器 | 读取多个 YAML、色板和 Prompt 文件 | 成功读入新字段不表示知道该怎样使用 |
| 普通 / weak Prompt 编译 | 主要使用 base.txt、negative.txt，以及选定色板对信息 | 只升级视觉签名，新的指令、条件和证据不会自动进入生图请求 |
| 风格检索 | 将整个视觉签名的值展开成搜索文本 | 新增反例、失败说明、来源标识也可能影响命中与排序 |
| 组合编译 | 调用相同的基础 Prompt 编译函数，再组合各部分 | 不会自动按新规则 ID 或适用条件筛选视觉内容 |
| Agent 直接读文件 | Agent 可能阅读全部结构化描述 | 与本地编译是不同路径，不能用其中一条的结果代表另一条 |

为验证编译行为，逐包加载后，仅在内存中替换 visual_signature，保持 Prompt、其他文件和主体请求不变，再对 generic、weak 两种配置分别比较：

- 405 个包完成探查，两个配置的最终正负 Prompt 都与替换前一致。
- 共调用编译函数 1,620 次；这些调用没有访问生图服务。
- 1 个包在旧加载器就失败：[american-luminism/provenance.yaml 第 8 行](../style-packages/movements/american-luminism/provenance.yaml#L8) 的标题含未加引号的冒号。
- 在索罗亚单例中还保存了前后相同的 Prompt SHA-256，详见 JSON 报告。

这说明当前编译路径会忽略这部分结构化规则载荷。它不说明规则本身没有美术作用，也不说明 Agent 读包方式必然无效。旧解析缺陷应单独修复并记录，不能混入新旧风格效果比较。

## 4. 自动化边界

| 工作 | 可以让脚本做什么 | 需要判断或验证的部分 |
| --- | --- | --- |
| 原文提取 | 逐条复制，保留源文件、原始路径和内容哈希，输出待审清单 | 原句到底是风格特征、题材、制作方法还是通用提醒 |
| 临时规则编号 | 为候选记录生成可追踪的临时 ID | 规则合并、拆分后的长期语义 ID |
| 来源整理 | 保留已有 asset_id、URL、作者与许可原文，查重复和失效路径 | 来源是否真正支持某条观察，能否作本次模型输入 |
| 键名映射 | 对已人工确认的结构做显式映射；无法映射就报出 | light、value、palette 等概念不是在所有包中同义 |
| 字段补齐 | 留空或标 pending，并检查必填项 | 不应自动补出历史事实、反例、适用条件或 verified |
| 规则编译 | 只发送已选择且审核过的指令，记录实际使用的规则 ID | 初期由人工或固定方向清单选择适用规则，不自动解释自然语言条件 |
| 效果评估 | 检查尺寸、网格、字符、路径、记录完整性；汇总评审结果 | 风格是否成立、差异是否合理、有没有内容泄漏 |
| 成熟度与发布 | 根据明确验收记录检查门槛 | 不能因 YAML 更整齐、句子更长就升级成熟度或替换代表图 |

典型失败包括：丢掉否定词，把条件性的笔触写成所有场景必须存在，把学校名称推成固定色板，把题材误当作风格不变量，或者为没有证据的句子自动绑定一个看似相关的馆藏链接。

尤其需要避免“先批量自动重写，再抽样看几个”。语法一致的模板可能让大量包同时变得通用，普通格式检查难以发现。

## 5. 三种成本路线

以下是后续工作量的规划假设，不是已计时的报价。1 人日按 8 人时计算；模型费用、服务排队和补充作品研究的不可预期等待单独计算。

| 路线 | 后续人工投入假设 | 收益与限制 |
| --- | --- | --- |
| 仅保真提取与差异清单 | 约 4–12 人时 | 获得可审查清单和原文追踪；不会自然改善美术效果 |
| 三方向旁路试点 | 约 25–50 人时，约 3–7 人日 | 能检验新规则是否值得采用；保留旧包默认行为，推荐先做 |
| 全库内容升级 | 必须按试点实耗重新估算 | 主要成本是逐包研究、编辑与效果审查，不能按脚本运行时间报价 |

三方向试点的拆解：

| 部分 | 人时估计 | 范围 |
| --- | --- | --- |
| 建立运行基线与最小兼容执行路径 | 12–24 | 先单列旧加载缺陷；旧路径输出快照，新路径显式选择与确定性编译，检索避免混入反例；不实现通用自然语言规则引擎 |
| 三个方向的美术研究与规则审阅 | 9–18 | 索罗亚的选定日光方向、包豪斯的特定纸材方法、ASCII 制作约束；不把文档样稿当已完成研究 |
| 执行、审查、记录和一次修订 | 4–8 | 36 张文本生图初筛与三个 ASCII 任务；包含失败记录和规则差异说明 |
| 合计 | 25–50 | 需要更多参考或多轮返工时会超出该区间，试点后再更新 |

为说明全库规模，可做敏感性计算：如果每个包的内容研究、整理和审阅平均耗时 1、2、3 小时，则 406 个包分别需要 **406、812、1,218 人时**。这不是对每包实际工时的预测，也不包含下列新增成本；学院拆方向或来源不足的包可能明显超过平均值。

- 如果每个包都做 18 张相同规模的初筛，理论上需要 7,308 张输出。真实计划应扣除确定性媒介并按各类任务调整；不能机械复用同一套题材。
- 假设每张输出初步评审 1–3 分钟，7,308 张约增加 122–365 人时；深度原作比对和返工另计。
- 如果每包平均修改 8 个现有文件，406 包就是 3,248 个文件改动；这是影响范围示例，不是建议的迁移任务量。
- 既有 L3 图片可以保留为旧版本证据。改变规则后需重新检查适用性，不能把全部旧 accepted 状态直接继承。

生图费用以实际模型每次请求价格乘以预算请求数计算，本评估不猜测统一单价，也不把生成次数当作图片有效数量。

## 6. 建议的执行顺序与停止条件

### 阶段 A：保持正式包不变，建立基线

保存源文件哈希、实际编译文本、模型与参数、当前参考输入和已有结果。旧加载问题单独修复。分别记录本地编译与 Agent 读包两种方式，避免把它们混为一个基线。

本轮已经完成全库结构盘点及编译探查；其余基线采样需要实际试验时建立。没有发生正式包迁移。

### 阶段 B：完成三个方向试点，再逐个登记

复用现有设计样稿与 [对照计划](design/art-style-pack-v2/comparison-plan.yaml)，逐条选择保留、改写、删除、拆分或待证。

初始试验使用独立目录和显式模式。当前索罗亚方向已登记为单个正式包的可选实验文件；包豪斯纸材和 ASCII 仍独立存放。正式包的默认 v1 入口保持原行为，新增方向需显式启用；规则、素材和结果各自带版本。

学院试点尤其不能把整个 Bauhaus 包直接改成纸材方向。纸材是新增的具体方向；原先适合平面、空间或功能设计的范围要保留并重新定义。相同原则适用于艺术家特定时期与抽象流派。

### 阶段 C：先验证差异，再决定启用

对同一用户请求比较名称提示、旧规则、新规则。逐项记录主体遵循、核心规则、联合判据、媒介完整性和近邻差异；保留全部输出。

出现以下情况先回到研究或执行适配，不扩库：

- YAML 变复杂，编译后的实际指令却没有变化。
- 新规则只改善一张封面，换题材后核心关系不再成立。
- 规则更鲜明，但经常改掉用户主体、场景或数量。
- 缩小范围带来的优势，被误称为“字段结构更好”。
- 为提升观感牺牲了 ASCII、像素或材料方法的硬约束。

达到启用条件后也不自动批量替换。每个包保留旧版本及来源追踪，按其内容变化处理版本和文档。回退应同时恢复规则、Prompt、参考选择、评估和默认路由，而不只是还原一个 YAML。

### 阶段 D：用实测工时决定后续规模

试点逐项记录研究、编辑、运行、审查和返工时间。下一批选择同类结构、来源充分的少量包，并由这些实耗估算批次成本。

试点只能验证所试方向，不能直接推出其余 403 个包都适合相同迁移。可以长期让新旧版本并存：新包采用经过验证的契约，旧包在被实际使用、发现问题或需要扩充时再升级。

## 7. 对前一版提案的调整

保留“有范围的 Art Bible、视觉规则、证据与对照验证”的内容目标，调整实施顺序：

**先做旁路增强与运行适配，证明收益后再启用具体方向；最后才考虑把视觉签名升级成统一规范源。**

此时唯一合理的自动迁移完成标准是“原信息保真、引用可追踪、待审项清楚”。美术升级完成标准还需要逐方向研究与实际输出证据。
