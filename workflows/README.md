# 创作工作流

风格包回答“画面用什么视觉语言表达”，创作工作流回答“输入素材经过什么步骤变成作品”。两者可以一起使用，但职责不同：工作流不应偷偷加入固定地点、人物、物件或故事，风格包也不应替代工作流对原始素材的保护要求。

## 目前提供的工作流

| 工作流 | 适合什么输入 | 输出方向 | 是否保留原图像素 |
| --- | --- | --- | --- |
| [摄影抽象编辑](photo-abstract-editorial/README.md) | 一张照片 | 照片与抽象编辑版式并置 | 是 |
| [场景聚合杂志](gathered-scenes-zine/README.md) | 一张照片 | 保留照片的杂志版式，或提炼为纸面作品 | 由变体决定 |

## 工作流和风格包怎样配合

建议按照下面的顺序编译：

```text
输入照片
   ↓
选择创作工作流
   ↓
确定是否保留原照片像素
   ↓
选择一个独立风格包（可选）
   ↓
只把风格包的视觉维度投射到允许的区域
   ↓
检查主体、授权、画幅和未请求元素
```

例如，可以先用“场景聚合杂志”的“保留照片”变体确定版式，再选择一个印刷或拼贴风格包处理纸张表面。也可以只使用工作流，不使用任何风格包。不要把工作流名称当成风格名称，也不要把示例中的照片题材当成默认生成内容。

## 四种使用方式

1. **交给有生图能力的 Agent**：把工作流目录连同自己的照片和目标交给 Agent，要求它先阅读 `workflow.yaml`，再编译任务。需要视觉语言时，再附上一个风格包目录。
2. **复制约束生成 Prompt**：打开 `workflow.yaml`，把 `purpose`、`allowed_axes` 和保护条件整理到自己的 Prompt 中，只替换主题、文字和画幅。
3. **交给支持 API 的 Agent**：配置你自己的模型 API Key，让 Agent 读取工作流和风格包后生成。OhMyStyle 不托管模型、Key 或生成图片。
4. **本地模型与 ComfyUI**：把输入照片、工作流约束、参考清单和输出尺寸分别接入本地节点；保留主体保护节点，避免风格节点反向改变题材。

## 外部工作流集成

OhMyStyle 登记了两个外部项目的兼容关系，但没有复制它们的 Skill、Prompt、示例图或品牌素材：

- [摄影抽象编辑外部项目](../integrations/README.md#摄影抽象编辑)
- [场景聚合杂志外部项目](../integrations/README.md#场景聚合杂志)

外部项目的许可证与 OhMyStyle 的许可证不同。使用者应从原作者仓库自行获取，并遵守原许可证；登记文件只用于说明来源、兼容工作流和禁止复制的边界。

## 给贡献者的最低要求

- 工作流必须有明确输入、输出、变体和保护条件。
- `subject_policy.default_subjects` 必须为空。
- 具体物件、地点、人物和故事只能作为用户输入或测试主体，不得写进默认工作流。
- 外部项目只登记链接和许可证，不把受限内容复制到本仓库。
- 新工作流使用 [`templates/workflow-package`](../templates/workflow-package) 起步，并运行 `python tools/validate-workflow.py`。
